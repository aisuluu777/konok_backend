## Уточнения владельца (важнее остального текста ТЗ)

- Переводимые тексты — отдельные поля на каждый язык: `<поле>_ky`, `<поле>_ru`, `<поле>_en`.
  Не JSON. Это касается и `regions` / `localities`.
- KYC — Boolean-поле `is_verified` у пользователя, его ставит и снимает admin.
- Водительское удостоверение — Boolean-поле `is_driver_license_verified`, его ставит и снимает admin.
- Никаких отдельных таблиц проверок, статусов KYC и провайдеров.

### Ответы владельца на вопросы этапа 0
- Регистрация и OTP — по email и паролю.
- Переводы: пользователи сами заполняют свои профили и активности на трёх языках; что не заполнено —
  переводит admin. Azure Translator не используется.
- Документы (ID, водительское удостоверение) пользователь загружает через API.
- Пользователь не может забронировать, не оплатив.
- Время выезда — 12:00.
- API для no-show не делать.
- Аренда авто: цена за день. Время получения авто обсуждается в чате и не отслеживается.
  Передача авто — по PIN. Отмена аренды — по той же шкале, что и проживание (100/80/60).
- Хозяин и авто видны в каталоге, только если у владельца одобрены документы (`is_verified`).
- Активности: цена за человека; докупка в статусах `confirmed` / `in_progress`.
- Админка — готовая панель SQLAdmin.
- Фото нужны у хозяина, авто, мест и активностей; медиа каждой сущности — в своей таблице.
- Отзывы — на проживание и аренду авто. Турист пишет на одном языке, переводы делает admin.
- Фоновые задачи — Redis + cron. HTTPS пока не нужен.
- Неоплаченных броней нет. Пока идёт оплата, бронь в статусе `pending_payment` занимает места
  (другие забронировать не могут); после оплаты — `confirmed`. Если гость отказался от оплаты,
  бронь удаляется; бронь, не оплаченная за 30 минут (`settings.payment_minutes`), удаляется
  фоновой задачей.
- Оплаченная бронь без заселения по PIN к 12:00 дня выезда получает статус `failed`.
- Уведомления (GET API + web push): напоминания хозяину, новое сообщение в чате, отмена брони,
  ответ поддержки.
- При отмене гостем активности возвращаются полностью (проживание / аренда — по шкале 100/80/60).
- Экстренная отмена admin — и для аренды авто: скрытая оценка 1 и закрытие дат — и для авто.
- Рейтинг не показывается, пока нет ни одного отзыва.
- Отзыв может оставить любой пользователь в любой момент; нельзя только о себе.
- Фоновые задачи — библиотека arq.
- Чат переводится через Azure AI Translator.
- Категорий у обращений в поддержку нет. Статуса `no_show` нет.
- Блокировка пользователя — флаг `users.is_active` (ставит admin).
- У авто показываются рейтинг и число отзывов.

## 1. Продукт

«Конок» — веб-платформа социального гостеприимства: гость бронирует проживание у местного жителя (хозяина), может купить у него активности и арендовать автомобиль.

- **Регион запуска:** только город Каракол.
- **Аудитория:** в основном жители Кыргызстана, также иностранные туристы.
- **Языки интерфейса:** кыргызский, русский, английский. Сайт переведён полностью.
- **Валюта:** только сомы (KGS). Поле валюты в таблицах не нужно.
- **Платформа:** адаптивный веб. Нативных приложений нет.

## 2. Стек и инфраструктура

- Python, FastAPI, SQLAlchemy, Pydantic, Alembic, Redis.
- Тестовая БД — Docker Compose.
- Деплой — AWS EC2 (t3.small), Ubuntu.
- Redis: OTP-коды и токены. Карточки хозяев **не кэшируются**.
- Аутентификация — JWT.
- Фоновые задачи нужны сейчас (напоминания хозяину, истечение неоплаченных броней, завершение броней). Инструмент для фоновых задач — **[ОТКРЫТО]**.
- Уведомления пользователю — web push + GET API списка уведомлений.

## 3. Роли и аккаунт

- Один аккаунт (один логин/пароль) на человека.
- Роли в системе: `user`, `admin`. Роли модератора нет — всю модерацию делает admin.
- «Хозяин» — это user, у которого есть профиль хозяина. «Владелец авто» — user, у которого есть автомобили. Отдельных ролей для них нет.
- Один человек может одновременно сдавать жильё и автомобиль.

## 4. Регионы и локации

Сейчас активен только Каракол, но новые регионы должны добавляться **без изменения кода**.

```
regions     (id, name_ky, name_ru, name_en, slug, is_active)
localities  (id, region_id → regions, name_ky, name_ru, name_en, slug, lat, lng, is_active)
```

- `host_profiles`, `places`, `vehicles` ссылаются на `locality_id` (ForeignKey), а не хранят город строкой.
- Строка «Каракол» не должна встречаться в коде, константах и enum. Только данные в БД (миграция Alembic с данными или админка).
- Фронт получает список активных локаций из API.
- Все правила (комиссия, время заезда, политика отмены) **одинаковы для всех регионов** — глобальные настройки, не по регионам.
- Часовой пояс один для всей страны: `Asia/Bishkek` (UTC+6).
- Если сейчас город где-то хранится строкой — нужна миграция в эту схему. Сначала покажи план миграции.

## 5. Переводы

- Тексты, которые вводят пользователи и админ (описания, названия), хранятся отдельными полями на каждый язык: `<поле>_ky`, `<поле>_ru`, `<поле>_en` (не JSON).
- При каждом сохранении текст переводится заново через Azure AI Translator. Проверки «текст не изменился» нет.
- Чат: сохраняется оригинал и перевод. Ошибка перевода не удаляет и не блокирует сообщение — показывается оригинал.

## 6. Верификация (KYC)

- Гость может бронировать **только после** проверки документа (ID). Проверка — вручную админом.
- KYC — Boolean-поле `users.is_verified`, его ставит и снимает admin.
- Владелец авто должен пройти KYC. Для аренды авто нужно подтверждённое водительское удостоверение —
  Boolean-поле `users.is_driver_license_verified`, его ставит и снимает admin.
- Отдельных таблиц проверок, статусов KYC и провайдеров нет.
- Способ KYC хозяина (Түндүк / международный провайдер / ручная проверка) — **[ОТКРЫТО]**.
- Юридическую сторону хранения документов решают другие люди — в код не закладывать ничего сверх обычной защиты доступа (документы видит только admin).

## 7. Профиль хозяина

- Незавершённая анкета хозяина не сохраняется — при выходе хозяин начинает заново.
- `is_published` выставляется автоматически при создании профиля.
- Показывается «на платформе с» — дата одобрения документов (KYC).
- Поля «дети» и «курение» — не нужны.
- Вместимость (кол-во гостей) и цена за человека задаёт хозяин.
- Рейтинг и счётчик отзывов — см. раздел 12.

## 8. Активности

- Хозяин создаёт свои активности сам, количество не ограничено.
- Цена обязательна, бесплатных активностей нет (с них берётся комиссия).
- Активность не привязана к конкретному дню.
- Комиссия — та же, что у брони (10%).
- Теги активностей создаёт только admin; хозяин только выбирает из них.
- Гость может оплатить проживание и активности вместе или докупить активности позже отдельно.

## 9. Места и избранное

- Места (`places`) добавляет только admin через админку.
- Пользователь добавляет/удаляет свои избранные.

## 10. Календарь и бронирование проживания

### Доступность
- Свободные места на дату = вместимость − забронированные места.
- Хозяин может заблокировать только свободные даты (без броней).
- Нельзя забронировать больше свободных мест. Защита от перепродажи при параллельных запросах обязательна.
- Гость не может иметь пересекающиеся брони у разных хозяев.
- Длительность проживания не ограничена. Бронь «на сегодня» разрешена.
- Стоимость = цена за человека × количество гостей × количество ночей.
- За остальных гостей в брони отвечает тот, кто бронировал.

### Подтверждение
- Бронь подтверждается **автоматически при успешной оплате**. Хозяин не может отклонить или отменить бронь.
- У хозяина есть кнопка «Вижу, жду гостя» — это отметка, а не статус брони.
- Напоминания хозяину (web push): сразу после брони, далее каждые 8 часов, пока он не нажмёт «Вижу, жду гостя». Ночной паузы нет.
- В админке — фильтр броней, где хозяин не нажал «Вижу, жду гостя» (админ звонит хозяину вручную).

### Время
- Заезд — 13:00 в день заезда.
- Время выезда — **[ОТКРЫТО]**.

### Заселение
- Подтверждение заселения — PIN. PIN не хешируется, гость видит его в личном кабинете.
- Блокировки по количеству попыток ввода PIN пока нет.

### Статусы (по текущей логике; если в коде иначе — сообщи)
- `created` — создана, не оплачена. Гость может отменить. Истекает, если не оплачена. Срок жизни неоплаченной брони — **[ОТКРЫТО]**.
- `confirmed` — оплачена, подтверждена.
- `in_progress` — заселение подтверждено PIN.
- `completed` — визит завершён.
- `cancelled_by_guest` — отмена гостем.
- `cancelled_by_admin` — экстренная отмена через поддержку.
- `no_show` — гость не приехал.

## 11. Отмены и возвраты

### Отмена гостем (проживание)
Отсчёт — от 13:00 дня заезда:

| До заезда | Возврат гостю |
|---|---|
| 72 ч и больше | 100% |
| от 48 до 72 ч | 80% |
| меньше 48 ч | 60% |

- С 13:00 дня заезда отмена гостем невозможна — бронь закрывается только через PIN или no-show.
- Удержанная часть уходит хозяину минус 10% комиссии.
- После отмены освободившиеся места снова доступны.
- Что получает хозяин при no-show, кто и когда ставит no-show — **[ОТКРЫТО]**.

### Отмена аренды авто
- Бесплатно до 24 ч до получения авто.
- Позже — возврат 60%.

### Экстренная отмена (хозяин не может принять гостя)
- Хозяин не отменяет бронь сам. Он создаёт обращение в поддержку, пока бронь в статусе `confirmed`.
- Отменяет только admin. Гостю — полный возврат, хозяину — ничего.
- Перебронирования к другому хозяину нет — только отмена.
- Admin при отмене отмечает, уважительная ли причина.
- Если причина неуважительная: в рейтинг хозяина добавляется скрытая оценка 1 (см. раздел 12), а даты отменённой брони блокируются в календаре хозяина.
- Все действия admin журналируются.

## 12. Отзывы и рейтинг

- Отзыв гость оставляет после завершённого визита.
- Рейтинг хозяина = среднее звёзд отзывов.
- Отмена хозяином по неуважительной причине = скрытая оценка 1: входит в среднее, **не** входит в счётчик отзывов и **не** показывается как отзыв («отменено хозяином» нигде публично не видно).
- У хозяина без отзывов показывается «0 отзывов», как у всех.

## 13. Чат

- Чат 1-на-1 между гостем и хозяином / владельцем авто.
- Автоперевод сообщений (раздел 5).
- Жалоба на сообщение/пользователя.

## 14. Финансы

- Комиссия платформы — 10% с каждой покупки (проживание, активности, аренда авто).
- Модель single-fee: гость видит итоговую цену, комиссия удерживается из суммы хозяину.
- Размер комиссии хранится в настройках. На брони сохраняется ставка на момент создания — изменение комиссии не влияет на существующие брони.
- Страховка — пока не реализуется.

## 15. Платежи — FreedomPay (Кыргызстан)

Документация: https://freedompay.kg/docs-en (именно KG, не .kz). API: `https://api.freedompay.kg`.

### Архитектура
- Интерфейс `PaymentProvider` (создать платёж, статус, возврат, выплата) с реализациями `MockPaymentProvider` и `FreedomPayProvider`. Выбор — через настройку окружения.
- Таблица платежей связана с бронью 1:N: проживание и активности, докупленные позже, — разные платежи.
- Каждая попытка оплаты получает свой уникальный `pg_order_id`.

### Приём оплаты
- Merchant API, платёжная страница FreedomPay (`init_payment.php`). Данные карт к нам не попадают.
- Одностадийная оплата (`pg_auto_clearing=1`): холд держится максимум 5 дней, а брони бывают на недели вперёд.
- Источник истины об оплате — серверный callback `result_url`. Редирект на `success_url` / `failure_url` — только для интерфейса, статус брони по нему не меняется.
- Обработчик `result_url`:
  - публичный, без авторизации;
  - проверяет подпись и сумму;
  - идемпотентный: FreedomPay повторяет вызов каждые 30 минут в течение 2 часов, на повтор ответ должен быть таким же, как на первый;
  - если бронь уже истекла/недоступна и `pg_can_reject=1` — отвечает `rejected`.
- Если ответ FreedomPay потерян — запросить статус (`get_status3.php`) по `pg_order_id` перед повтором.

### Подпись
- `pg_sig` = MD5 строки: `имя_скрипта;значения всех параметров, отсортированных по имени (включая pg_salt);secret_key`.
- Подписываются все запросы и ответы в обе стороны. Входящие сообщения с неверной подписью — отклонять.
- Ключей два: для платежей и для выплат.

### Возвраты
- `revoke.php` с `pg_refund_amount` — полный или частичный, можно несколько частичных.
- Возврат через API возможен только если по платежу `pg_can_reject=1` (карты). Для безотзывных способов — **[ОТКРЫТО]**.

### Режимы
- Новый мерчант работает в тестовом режиме до подписания Акта подключения.

### [ОТКРЫТО] по платежам — не реализовывать до решения
1. Способы оплаты: только карты или ещё мобильные банки / ELQR / кошельки.
2. Как возвращать деньги за безотзывные способы оплаты.
3. Выплаты хозяевам: способ (карта/токен/другое), пополнение выплатного баланса, момент выплаты.
4. Код валюты KGS в `pg_currency` (в документации указаны только KZT/USD/EUR).
